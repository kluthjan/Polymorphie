🎭 Alltagsbeispiel: Was ist Polymorphie überhaupt?

Stell dir vor, du rufst alle Mitarbeiter eines Büros an und sagst: "Bitte unterschreibt das Dokument!" Der Aufruf ist für alle gleich. Aber jeder unterschreibt anders – mit seinem eigenen Namen. Das ist Polymorphie: gleicher Befehl, unterschiedliches Ergebnis je nach Person (Objekt).

In Java: Du rufst bei verschiedenen Objekten dieselbe Methode auf (datenAusgeben()), aber jedes Objekt reagiert mit seiner eigenen Version davon.

🧬
Konzept 1: Vererbung mit extends

Was bedeutet das? Mit extends sagt eine Klasse: "Ich bin ein Spezialfall von einer anderen Klasse." Die Unterklasse erbt automatisch alle Attribute und Methoden der Oberklasse.

Analogie: Ein Laptop ist ein Gerät. Ein Hund ist ein Tier. Die Oberklasse ist der allgemeine Begriff, die Unterklasse ist der spezifische.

Vererbung – Grundprinzip
// Oberklasse = der allgemeine Bauplan
public class Tier {
    public void geraeuschMachen() {
        System.out.println("Das Tier macht ein Geräusch.");
    }
}

// Unterklasse = erbte alles von Tier, ist aber spezieller
public class Hund extends Tier {  // ← "Hund IST EIN Tier"
    // Hund hat automatisch geraeuschMachen() geerbt!
    // Wir können sie überschreiben (oder auch nicht)
}
💡
Merksatz

Immer wenn du sagen kannst "X ist ein Y", dann macht Vererbung Sinn. Laptop ist ein Gerät ✅ · Drucker ist ein Gerät ✅ · Gerät ist ein Laptop ❌

🔧
Konzept 2: Methoden überschreiben mit @Override

Was bedeutet das? Mit @Override sagst du Java: "Diese Methode existiert schon in der Oberklasse, aber ich möchte für meine Klasse ein anderes Verhalten definieren." Die Methode bekommt denselben Namen, aber einen neuen Rumpf (neue Anweisungen).

Warum schreibt man @Override dazu? Eigentlich ist @Override optional, aber es ist sehr sinnvoll! Wenn du den Methodennamen falsch schreibst (z.B. geraeuschMache statt geraeuschMachen), bekommst du ohne @Override keinen Fehler – du denkst du überschreibst, aber du erstellst eine neue Methode. Mit @Override sagt Java sofort: "Fehler!"

@Override in Aktion
public class Hund extends Tier {

    @Override  // ← sagt Java: "Ich überschreibe eine Methode aus Tier"
    public void geraeuschMachen() {
        // Jetzt kommt unser NEUES Verhalten:
        System.out.println("Der Hund bellt.");
        // Die Version aus Tier ("Das Tier macht...") wird NICHT aufgerufen!
    }
}
⬆️
Konzept 3: super() und super.methode()

super(...) im Konstruktor: Wenn eine Unterklasse einen Konstruktor hat, muss sie den Konstruktor der Oberklasse aufrufen – mit super(...). Das muss die erste Zeile des Konstruktors sein. Es ist quasi wie: "Erst mach alles was Geraet beim Erstellen macht, dann mache ich meinen Laptop-spezifischen Teil."

super.methode() in einer Methode: Du kannst von der überschriebenen Methode aus trotzdem die Version der Oberklasse aufrufen. Das ist nützlich, wenn du die Basis-Ausgabe willst und nur etwas ergänzen möchtest.

super() und super.methode()
public class Laptop extends Geraet {

    private int ramGb;

    public Laptop(String inv, String hersteller, String modell,
                   String standort, String status, int ramGb) {
        super(inv, hersteller, modell, standort, status); // ← MUSS erste Zeile sein!
        // ↑ Ruft Geraet(...) auf → befüllt inventarnummer, hersteller usw.
        this.ramGb = ramGb; // ← nur der Laptop-eigene Wert kommt hier dazu
    }

    @Override
    public void datenAusgeben() {
        super.datenAusgeben(); // ← ruft Geraet.datenAusgeben() auf
        // ↑ Gibt Inventarnummer, Hersteller, Modell, Standort, Status aus
        System.out.println("RAM: " + ramGb + " GB"); // ← danach der Laptop-Teil
    }
}
⚠️
Warum kann Laptop nicht direkt auf inventarnummer zugreifen?

Die Attribute in Geraet sind private. Das bedeutet: Nur Geraet selbst darf direkt darauf zugreifen. Laptop erbt die Attribute, kann sie aber nicht direkt lesen. Deshalb rufen wir super.datenAusgeben() auf – das erledigt Geraet für uns.

🔍
Konzept 4: Statischer & Dynamischer Typ

Das ist das Herzstück der Polymorphie! Bei dieser Zeile gibt es zwei verschiedene Typen:

Zwei Typen in einer Zeile
  Geraet  geraet1  =    new Laptop(...)  ;
    ↑                        ↑
Statischer Typ          Dynamischer Typ
(links, Compiler)       (rechts, Laufzeit)
🔴 Statischer Typ = Geraet

Das ist was der Compiler sieht (bevor das Programm läuft). Er erlaubt nur Methoden aufzurufen, die in Geraet bekannt sind. Du kannst keine Laptop-spezifischen Methoden aufrufen, solange die Variable den Typ Geraet hat.

🟢 Dynamischer Typ = Laptop

Das ist was zur Laufzeit wirklich im Speicher liegt (wenn das Programm ausgeführt wird). Java schaut auf den dynamischen Typ und entscheidet: "Welche Version von datenAusgeben() führe ich aus?" → Die von Laptop!

🎯
Das ist Polymorphie – dynamisches Binden (Late Binding)

Java entscheidet erst zur Laufzeit (nicht beim Compilieren), welche Methode aufgerufen wird. Dieser Mechanismus heißt dynamisches Binden oder Late Binding. Der statische Typ sagt: "Was darf ich aufrufen?" Der dynamische Typ sagt: "Welche Version wird ausgeführt?"

Hauptaufgabe 1

Tiere – Polymorphie mit einfachen Klassen

Aufgabenstellung: Erstelle eine Oberklasse Tier mit der Methode geraeuschMachen(). Erstelle dann die Unterklassen Hund, Katze und Kuh, die jeweils die Methode überschreiben. In Main.java sollen alle Variablen den Typ Tier haben, aber auf Unterklassenobjekte zeigen.

🐾 Die Idee hinter dieser Aufgabe

Stell dir vor, du arbeitest in einer Tierklinik. Du hast eine Methode behandeln(Tier tier). Diese Methode funktioniert für alle Tiere – egal ob Hund, Katze oder Kuh. Du musst nicht für jedes Tier eine eigene Behandlungsmethode schreiben. Das spart Code und macht dein Programm flexibler.

Tier
Hund → "Der Hund bellt."
Katze → "Die Katze miaut."
Kuh → "Die Kuh muht."
1
Tier.java erstellen – Die Oberklasse
Neue Java-Datei anlegen & Methode schreiben
▼
📋 Schritt-für-Schritt: So löst du das
  1. Rechtsklick auf den src-Ordner im Package Explorer → New → Class
  2. Name: Tier eingeben → Finish
  3. Schreibe die Methode geraeuschMachen() in die Klasse
  4. Die Methode ist public void – sie gibt nichts zurück und ist von außen aufrufbar
  5. Speichern: Strg + S

Die Klasse Tier ist die Oberklasse (auch: Basisklasse, Superklasse). Sie enthält nur das Allgemeine – ein Tier macht irgendein Geräusch. Die Unterklassen werden später definieren, welches Geräusch genau.

Tier.java
/**
 * Tier ist die Oberklasse – der allgemeine Bauplan.
 * Sie definiert: JEDES Tier kann ein Geräusch machen.
 * WAS für ein Geräusch, bestimmt die jeweilige Unterklasse.
 */
public class Tier {

    /**
     * Diese Methode gibt ein allgemeines Geräusch aus.
     * Sie wird von Hund, Katze und Kuh mit @Override
     * mit einem spezifischen Geräusch überschrieben.
     */
    public void geraeuschMachen() {
        System.out.println("Das Tier macht ein Geräusch.");
    }
}
💡
Warum hat Tier keine Attribute?

In dieser Aufgabe brauchen wir keine Eigenschaften wie Name oder Alter. Tier hat nur die Methode. Das ist vollkommen gültig! Klassen können auch nur aus Methoden bestehen.

2
Hund.java erstellen – Erste Unterklasse
extends + @Override – Methode überschreiben
▼
📋 Schritt-für-Schritt: So löst du das
  1. Neue Klasse Hund erstellen (Rechtsklick → New → Class)
  2. Im Dialog bei "Superclass" kannst du Tier eintragen – oder du schreibst es manuell als extends Tier
  3. Eclipse zeigt ggf. einen roten Strich, wenn du @Override hinzufügst – das verschwindet sobald du die Methode korrekt schreibst
  4. Schreibe @Override in die Zeile über die Methode
  5. Schreibe den Methodenrumpf mit der richtigen Ausgabe

Mit extends Tier sagt die Klasse Hund: "Ich bin ein Tier – ich erbe alles von Tier." Der Hund bekommt automatisch die Methode geraeuschMachen(). Mit @Override sagt der Hund dann: "Aber ich führe diese Methode auf meine eigene Art aus."

Hund.java
/**
 * Hund ERBT von Tier (extends Tier).
 * Das bedeutet: Hund IST EIN Tier.
 * Hund hat automatisch die Methode geraeuschMachen() geerbt –
 * überschreibt sie aber mit dem Bellen.
 */
public class Hund extends Tier {

    @Override  // ← Markiert: Diese Methode kommt aus der Oberklasse Tier
    public void geraeuschMachen() {
        // Nicht mehr "Das Tier macht ein Geräusch." –
        // jetzt kommt das Hunde-spezifische Verhalten:
        System.out.println("Der Hund bellt.");
    }
}

Katze und Kuh werden exakt gleich aufgebaut – nur der Klassenname und die Ausgabe ändern sich:

Katze.java
public class Katze extends Tier {

    @Override
    public void geraeuschMachen() {
        System.out.println("Die Katze miaut.");
    }
}
Kuh.java
public class Kuh extends Tier {

    @Override
    public void geraeuschMachen() {
        System.out.println("Die Kuh muht.");
    }
}

Main.java – Polymorphie in Aktion
Variablen vom Typ Tier, aber Unterklassen-Objekte
▼
📋 Schritt-für-Schritt: So löst du das
  1. In Main.java in der main()-Methode: Erstelle drei Variablen
  2. Der Typ links muss Tier sein (nicht Hund, nicht Katze!)
  3. Rechts bei new steht der konkrete Typ (Hund, Katze, Kuh)
  4. Rufe auf jeder Variable geraeuschMachen() auf
  5. Beobachte: obwohl alle Variablen Typ Tier haben, gibt jede etwas anderes aus
  6. Schreibe den Kommentar mit der Erklärung (Schritt 6 der Aufgabe)
Main.java – Hauptaufgabe 1
public class Main {
    public static void main(String[] args) {

        // Statischer Typ: Tier  ← steht LINKS bei der Variable
        // Dynamischer Typ: Hund ← steht RECHTS bei new
        Tier tier1 = new Hund();
        Tier tier2 = new Katze();
        Tier tier3 = new Kuh();

        // GLEICHER AUFRUF – aber Java schaut: Was ist tier1 tatsächlich?
        // tier1 ist ein Hund → also: Hund.geraeuschMachen() → "Der Hund bellt."
        tier1.geraeuschMachen();

        // tier2 ist eine Katze → Katze.geraeuschMachen() → "Die Katze miaut."
        tier2.geraeuschMachen();

        // tier3 ist eine Kuh → Kuh.geraeuschMachen() → "Die Kuh muht."
        tier3.geraeuschMachen();

        // ── ERKLÄRUNG (Schritt 6) ──────────────────────────────────────────
        // Alle Variablen haben den Typ Tier (statischer Typ).
        // Tatsächlich sind es aber Hund, Katze und Kuh (dynamischer Typ).
        // Java entscheidet ERST ZUR LAUFZEIT, welche Methode aufgerufen wird.
        // Das nennt man "dynamisches Binden" – und genau das ist Polymorphie!
    }
}
🖥️ Ausgabe in Eclipse (Console)
Der Hund bellt.
Die Katze miaut.
Die Kuh muht.
✅
Warum ist das Polymorphie?

Der Methodenaufruf geraeuschMachen() ist bei allen drei Variablen identisch. Java schaut aber zur Laufzeit: "Was steckt wirklich in der Variable?" und ruft die richtige überschriebene Methode auf. Gleicher Code – verschiedene Ergebnisse je nach Objekt. Das ist Polymorphie.

Hauptaufgabe 2

IT-Geräte polymorph verwalten

Aufgabenstellung: Erstelle die Klassen Geraet, Laptop, Drucker und Switch. Die Unterklassen sollen von Geraet erben und die Methode datenAusgeben() überschreiben. In Main.java sollen polymorphe Variablen verwendet werden.

💼 Die Idee hinter dieser Aufgabe

In einer Firma gibt es eine IT-Inventarliste. Alle Geräte haben gemeinsame Felder: Inventarnummer, Hersteller, Modell, Standort, Status. Aber ein Laptop hat zusätzlich einen RAM-Wert, ein Drucker hat ein Druckverfahren, ein Switch hat Ports und einen Managed-Status.

Mit Vererbung und Polymorphie kannst du alle Geräte über denselben "Bauplan" (Geraet) verwalten, ohne Code doppelt zu schreiben. Die gemeinsamen Felder stehen einmal in Geraet – die spezifischen in den Unterklassen.

Geraet (inventarnummer, hersteller, modell, standort, status)
Laptop + ramGb (int)
Drucker + druckverfahren (String)
Switch + anzahlPorts (int) + managed (boolean)
1
Geraet.java – Die Oberklasse mit Attributen
private Attribute · Konstruktor mit this · Getter & Setter · datenAusgeben()
▼
📋 Schritt-für-Schritt: So löst du das
  1. Neue Klasse Geraet erstellen
  2. Schreibe die 5 privaten Attribute ganz oben in die Klasse (vor dem Konstruktor)
  3. Schreibe den Konstruktor: public Geraet(String inventarnummer, String hersteller, ...)
  4. Im Konstruktor: Befülle jedes Attribut mit this.attribut = parameter;
  5. Schreibe Getter getStatus() und Setter setStatus(String status)
  6. Schreibe die Methode datenAusgeben() die alle 5 Attribute ausgibt

Warum private? Das nennt man Kapselung (Encapsulation). Die Attribute sind von außen nicht direkt änderbar. Man kann sie nur über definierte Methoden lesen (Getter) oder ändern (Setter). Das schützt die Daten vor unbeabsichtigten Änderungen.

Warum this.inventarnummer = inventarnummer? Weil der Parameter des Konstruktors denselben Namen hat wie das Attribut. Mit this.inventarnummer meinst du das Attribut der Klasse; ohne this würde Java denken du meinst den Parameter.

Geraet.java
/**
 * Geraet ist die Oberklasse für alle IT-Geräte.
 * Sie enthält die gemeinsamen Felder und Methoden.
 */
public class Geraet {

    // ── ATTRIBUTE (private = nur innerhalb dieser Klasse direkt zugänglich) ──
    private String inventarnummer;   // z.B. "IT-1001"
    private String hersteller;        // z.B. "Lenovo"
    private String modell;            // z.B. "ThinkPad T14"
    private String standort;          // z.B. "Raum 101"
    private String status;            // "aktiv" / "offline" / "wartung"

    // ── KONSTRUKTOR ───────────────────────────────────────────────────────────
    // Wird aufgerufen wenn man: new Geraet("IT-1001", "Lenovo", ...) schreibt
    public Geraet(String inventarnummer, String hersteller,
                   String modell, String standort, String status) {

        // "this.inventarnummer" = das ATTRIBUT dieser Klasse
        // "inventarnummer" ohne this = der PARAMETER des Konstruktors
        this.inventarnummer = inventarnummer;
        this.hersteller  = hersteller;
        this.modell      = modell;
        this.standort    = standort;
        this.status      = status;
    }

    // ── GETTER & SETTER ───────────────────────────────────────────────────────
    // Getter: Gibt den Wert nach außen zurück (nur lesen)
    public String getStatus() {
        return status;
    }

    // Setter: Erlaubt den Wert von außen zu ändern (kontrolliert)
    public void setStatus(String status) {
        this.status = status;
    }

    // ── METHODE ──────────────────────────────────────────────────────────────
    // Diese Methode wird von den Unterklassen mit @Override erweitert.
    // Laptop, Drucker und Switch rufen sie mit super.datenAusgeben() auf.
    public void datenAusgeben() {
        System.out.println("Inventarnummer: " + inventarnummer);
        System.out.println("Hersteller:     " + hersteller);
        System.out.println("Modell:         " + modell);
        System.out.println("Standort:       " + standort);
        System.out.println("Status:         " + status);
    }
}
2
Laptop.java – Unterklasse mit super() im Konstruktor
extends Geraet · super(...) · @Override · super.datenAusgeben()
▼
📋 Schritt-für-Schritt: So löst du das
  1. Neue Klasse Laptop mit extends Geraet erstellen
  2. Füge das Laptop-eigene Attribut private int ramGb; hinzu
  3. Erstelle den Konstruktor: Er bekommt alle Geraet-Parameter plus int ramGb
  4. Im Konstruktor als ERSTE ZEILE: super(inventarnummer, hersteller, modell, standort, status);
  5. Danach: this.ramGb = ramGb;
  6. Überschreibe datenAusgeben() mit @Override
  7. In der Methode: Als erstes super.datenAusgeben();, dann RAM ausgeben

Warum muss super(...) die erste Zeile sein? Java erzwingt das. Die Oberklasse muss zuerst komplett initialisiert werden, bevor die Unterklasse ihre eigenen Dinge erledigt. Es wäre sonst möglich, auf Attribute zuzugreifen, die noch gar nicht existieren.

new Laptop("IT-1001", "Lenovo", ..., 16)
→
super(...) → Geraet-Konstruktor
→
this.ramGb = 16
→
Laptop-Objekt fertig!
Laptop.java
public class Laptop extends Geraet {   // Laptop IST EIN Geraet

    // Laptop-eigenes Attribut (zusätzlich zu den Geraet-Attributen)
    private int ramGb;

    // Konstruktor: Nimmt alle Geraet-Parameter PLUS ramGb entgegen
    public Laptop(String inventarnummer, String hersteller, String modell,
                   String standort, String status, int ramGb) {

        super(inventarnummer, hersteller, modell, standort, status);
                // ↑ MUSS die erste Zeile sein! Ruft Geraet(String,String,String,String,String) auf.
                //   Der Geraet-Konstruktor befüllt: inventarnummer, hersteller, modell, standort, status

        this.ramGb = ramGb;   // Nur der Laptop-eigene Wert kommt hier dazu
    }

    @Override
    public void datenAusgeben() {
        super.datenAusgeben();
                // ↑ Ruft Geraet.datenAusgeben() auf → gibt alle 5 Basis-Felder aus
                //   (inventarnummer, hersteller, modell, standort, status)
                //   WARUM: inventarnummer usw. sind private in Geraet –
                //   Laptop kann sie nicht direkt ansprechen!

        System.out.println("RAM:            " + ramGb + " GB");
                // ↑ Nur der Laptop-eigene Teil wird hier ergänzt
    }
}

Drucker.java & Switch.java – Gleiches Muster, andere Attribute
Druckverfahren (String) · anzahlPorts (int) · managed (boolean)
▼

Drucker und Switch werden exakt nach demselben Muster wie Laptop aufgebaut – nur die spezifischen Attribute unterscheiden sich. Für Switch kommt der Datentyp boolean hinzu.

📌
Was ist ein boolean?

Ein boolean kann nur zwei Werte haben: true (wahr) oder false (falsch). Bei managed: true = der Switch ist konfigurierbar (managed Switch, teurer). false = einfacher Switch ohne Konfiguration (unmanaged).

Drucker.java
public class Drucker extends Geraet {

    private String druckverfahren;   // "Laserdruck" / "Tintenstrahl" / "Thermodruck"

    public Drucker(String inventarnummer, String hersteller, String modell,
                    String standort, String status, String druckverfahren) {
        super(inventarnummer, hersteller, modell, standort, status); // Geraet befüllen
        this.druckverfahren = druckverfahren;                         // Drucker-eigener Wert
    }

    @Override
    public void datenAusgeben() {
        super.datenAusgeben();                                            // Basis-Daten
        System.out.println("Druckverfahren: " + druckverfahren);       // Drucker-spezifisch
    }
}
Switch.java
public class Switch extends Geraet {

    private int     anzahlPorts;   // z.B. 8, 24, 48
    private boolean managed;       // true = managed (konfigurierbar) / false = unmanaged

    public Switch(String inventarnummer, String hersteller, String modell,
                   String standort, String status, int anzahlPorts, boolean managed) {
        super(inventarnummer, hersteller, modell, standort, status);
        this.anzahlPorts = anzahlPorts;
        this.managed     = managed;
    }

    @Override
    public void datenAusgeben() {
        super.datenAusgeben();
        System.out.println("Anzahl Ports:   " + anzahlPorts);

        // Ternärer Operator: (Bedingung) ? "wenn true" : "wenn false"
        // Gibt "Ja" aus wenn managed=true, sonst "Nein"
        System.out.println("Managed:        " + (managed ? "Ja" : "Nein"));
    }
}

Hauptaufgabe 3

Polymorphes Array mit Schleife

Aufgabenstellung: Erstelle ein Array vom Typ Geraet[] mit 6 Einträgen (2 Laptops, 2 Drucker, 2 Switches). Gib alle Geräte mit einer Schleife aus. Zähle Geräte nach Status. Ändere einen Status mit setStatus().

📦 Die Idee: Warum ist das Array so mächtig?

Ohne Polymorphie bräuchtest du 3 separate Arrays: Laptop[] laptops, Drucker[] drucker, Switch[] switches – und 3 separate Schleifen. Mit Polymorphie reicht ein Array und eine Schleife. Wenn du später eine neue Geräteklasse Tablet hinzufügst, funktioniert die Schleife sofort ohne Änderungen!

1
Array erstellen und mit 6 Geräten befüllen
Geraet[] – 2 Laptops, 2 Drucker, 2 Switches
▼

💡
Warum kann ein Laptop in ein Geraet[] gespeichert werden?

Laptop extends Geraet → Laptop IST ein Geraet. Genau wie ein Hund ein Tier ist und in ein Tier[] passt. Java erlaubt es, Unterklassenobjekte in Arrays der Oberklasse zu speichern.

Main.java – Array befüllen

2
Alle Geräte mit for-Schleife ausgeben
Immer gleicher Aufruf – automatisch richtige Version
▼
📋 Schritt-für-Schritt: So löst du das
  1. Schreibe eine for-Schleife: for (int i = 0; i < geraete.length; i++)
  2. Im Schleifenrumpf: Gib zuerst eine Trennzeile aus: System.out.println("--- Gerät " + (i+1) + " ---");
  3. Dann: geraete[i].datenAusgeben(); – Java ruft automatisch die richtige Version auf
  4. Danach: System.out.println(); für eine Leerzeile zwischen den Geräten
Main.java – Schleife ausgeben
for (int i = 0; i < geraete.length; i++) {
    System.out.println("--- Gerät " + (i + 1) + " ---");

    geraete[i].datenAusgeben();  // ← IMMER gleicher Aufruf!
        // Java schaut: Was ist geraete[i] tatsächlich?
        // i=0: Laptop  → Laptop.datenAusgeben()  (inkl. RAM)
        // i=1: Laptop  → Laptop.datenAusgeben()  (inkl. RAM)
        // i=2: Drucker → Drucker.datenAusgeben() (inkl. Druckverfahren)
        // i=3: Drucker → Drucker.datenAusgeben() (inkl. Druckverfahren)
        // i=4: Switch  → Switch.datenAusgeben()  (inkl. Ports + Managed)
        // i=5: Switch  → Switch.datenAusgeben()  (inkl. Ports + Managed)

    System.out.println(); // Leerzeile zwischen Geräten
}
🎯
Das ist der Kern der Polymorphie!

Eine Schleife, ein Aufruf – und Java macht automatisch das Richtige. Ohne Polymorphie bräuchtest du 3 separate Schleifen mit if (geraete[i] instanceof Laptop) usw. Das ist unelegant und fehleranfällig.

  2. Schleife über das Array
  3. In der Schleife: String status = geraete[i].getStatus(); – Getter verwenden!
  4. Mit if/else if den Status prüfen und den passenden Zähler erhöhen (++)
  5. Nach der Schleife: Zähler ausgeben
⚠️
Strings immer mit .equals() vergleichen, nie mit ==

status == "aktiv" → ❌ FALSCH! In Java vergleicht == bei Strings die Speicheradresse, nicht den Inhalt. Verwende immer status.equals("aktiv") → ✅ RICHTIG!

Main.java – Status auswerten & ändern
// ── Zähler initialisieren ──────────────────────────────────────────────────
int aktiveGeraete  = 0;
int offlineGeraete = 0;
int wartungGeraete = 0;

// ── Status jedes Geräts prüfen ────────────────────────────────────────────
for (int i = 0; i < geraete.length; i++) {
    String status = geraete[i].getStatus();  // Getter aus Geraet aufrufen

    // equals() für String-Vergleich verwenden (NICHT ==)!
    if (status.equals("aktiv")) {
        aktiveGeraete++;
    } else if (status.equals("offline")) {
        offlineGeraete++;
    } else if (status.equals("wartung")) {
        wartungGeraete++;
    }
}

System.out.println("Offline Geräte: " + offlineGeraete);  // → 1
System.out.println("Wartung:        " + wartungGeraete);  // → 2

System.out.println("\nDrucker Canon wird repariert → Status auf aktiv");
geraete[3].setStatus("aktiv");  // Index 3 = Canon Drucker

Zusatzaufgabe 2

Spezielle Methode & instanceof

Aufgabe: Füge in Laptop eine Methode akkuStatusAusgeben() hinzu. Erstelle eine Variable vom Typ Geraet die auf ein Laptop-Objekt zeigt. Zeige, wie man die Laptop-spezifische Methode mit instanceof und Casting aufruft.

1
Das Problem verstehen
Warum funktioniert der direkte Aufruf nicht?
▼

Wenn eine Variable den statischen Typ Geraet hat, kennt der Java-Compiler nur die Methoden, die in Geraet definiert sind. akkuStatusAusgeben() existiert aber nur in Laptop – Geraet kennt sie nicht!

Das Problem
// Laptop.java: Diese Methode ist NUR in Laptop, NICHT in Geraet!
public void akkuStatusAusgeben() {
    System.out.println("Akku wird geprüft.");
}

// In Main.java:
Geraet g = new Laptop("IT-5001", "HP", "EliteBook", "Raum 3", "aktiv", 16);

// g.akkuStatusAusgeben(); ← COMPILERFEHLER!
// Eclipse zeigt: "The method akkuStatusAusgeben() is undefined for the type Geraet"
// Begründung: Der statische Typ von g ist Geraet.
// Der Compiler sieht nur was in Geraet definiert ist.
// akkuStatusAusgeben() steht nicht in Geraet → Compilerfehler!
2
Lösung: instanceof + Casting
Typ prüfen → sicher umwandeln → Methode aufrufen
▼
📋 Schritt-für-Schritt: So löst du das
  1. Verwende instanceof um zu prüfen: "Ist g wirklich ein Laptop?"
  2. Wenn ja: Caste (wandle den Typ um) mit (Laptop) g
  3. Speichere das Ergebnis in einer Laptop-Variable
  4. Rufe jetzt die Laptop-Methode auf
  5. Schreibe den Kommentar mit Erklärung
Main.java – instanceof + Casting
Geraet g = new Laptop("IT-5001", "HP", "EliteBook", "Raum 3", "aktiv", 16);

// SCHRITT 1: Mit instanceof sicher prüfen ob g ein Laptop ist
if (g instanceof Laptop) {
    // SCHRITT 2: Casting – "wandle g von Geraet-Typ in Laptop-Typ um"
    // Das nennt man DOWNCASTING (von Ober- zu Unterklasse)
    Laptop laptop = (Laptop) g;

    // SCHRITT 3: Jetzt hat laptop den statischen Typ Laptop
    // → alle Laptop-Methoden sind erreichbar!
    laptop.akkuStatusAusgeben();  // ✅ Kein Fehler mehr!
}

// Warum brauchen wir instanceof?
//   Stell dir vor, g wäre ein Drucker (new Drucker(...)).
//   Dann würde (Laptop) g zur Laufzeit einen ClassCastException-Fehler werfen!
//   instanceof prüft VORHER ob der Cast sicher ist.
//   Wenn g kein Laptop ist, wird der if-Block einfach übersprungen – kein Fehler!
🖥️ Ausgabe
Akku wird geprüft.
BegriffWas passiertBeispiel
instanceofPrüft zur Laufzeit: Ist das Objekt von diesem Typ?g instanceof Laptop → true/false
CastingWandelt den Typ der Variable um(Laptop) g
DowncastingVon Oberklasse zu UnterklasseGeraet → Laptop
UpcastingVon Unterklasse zu Oberklasse (automatisch)Geraet g = new Laptop()
Zusatzaufgabe 3

Abstrakte Klassen

Aufgabe: Ändere die Klasse Geraet zu einer abstrakten Klasse. Mache datenAusgeben() abstrakt. Prüfe dass new Geraet() nicht mehr funktioniert, aber new Laptop() weiterhin geht.

🏗️ Analogie: Bauplan vs. fertiges Haus

Eine abstrakte Klasse ist wie ein Bauplan. Ein Bauplan beschreibt, welche Räume ein Haus haben soll – aber man kann in einem Bauplan nicht wohnen. Man braucht ein konkretes Haus (Unterklasse). Genauso: Man kann kein abstraktes Tier erstellen, aber einen Hund schon.

1
Abstrakte Klasse & abstrakte Methode verstehen
abstract class · abstract void · basisDatenAusgeben()
▼
📋 Schritt-für-Schritt: So löst du das (am Beispiel Ticket)
  1. Schreibe public abstract class Ticket (abstract vor class)
  2. Abstrakte Methoden haben keinen Rumpf: public abstract void datenAusgeben(); – kein {}!
  3. Nicht-abstrakte Methoden (basisDatenAusgeben()) behalten ihren Rumpf
  4. Unterklassen müssen alle abstrakten Methoden mit @Override implementieren
  5. In den Unterklassen: basisDatenAusgeben() aufrufen (ohne super., da nicht überschrieben)
❌ Normale Klasse

new Geraet() ist erlaubt. Man könnte ein "leeres" Geraet erzeugen, das gar nichts Sinnvolles tut. Das wollen wir verhindern.

✅ Abstrakte Klasse

new Geraet() → Compilerfehler. Man muss immer eine konkrete Unterklasse (Laptop, Drucker, Switch) verwenden.

Ticket.java – abstrakte Klasse (für Zusatzaufgabe 4)
// "abstract" vor "class" = kein new Ticket() möglich!
public abstract class Ticket {

    // Gemeinsame Attribute (protected = auch für Unterklassen zugänglich)
    protected String ticketnummer;
    protected String titel;
    protected String beschreibung;
    protected String status;

    // Konstruktor (auch abstrakte Klassen können Konstruktoren haben!)
    public Ticket(String ticketnummer, String titel,
                   String beschreibung, String status) {
        this.ticketnummer = ticketnummer;
        this.titel        = titel;
        this.beschreibung = beschreibung;
        this.status       = status;
    }

    // ── ABSTRAKTE METHODEN (kein Rumpf, kein {}!) ─────────────────────────
    // Alle Unterklassen MÜSSEN diese Methoden implementieren!
public abstract void datenAusgeben();       // ← kein Rumpf!
public abstract String prioritaetBerechnen(); // ← kein Rumpf!

    // ── NORMALE (nicht-abstrakte) METHODE ─────────────────────────────────
    // Hat einen Rumpf → Unterklassen können sie aufrufen
    public void basisDatenAusgeben() {
        System.out.println("Ticketnummer: " + ticketnummer);
        System.out.println("Titel:        " + titel);
        System.out.println("Beschreibung: " + beschreibung);
        System.out.println("Status:       " + status);
    }

    public String getStatus() { return status; }
    public void setStatus(String s) { this.status = s; }
}
🚫
Dieser Code funktioniert nicht mehr!

Ticket t = new Ticket(...); → Compilerfehler: "Cannot instantiate the type Ticket"
Das ist gewollt! Man braucht immer eine konkrete Unterklasse.

✅
Das funktioniert weiterhin!

Ticket t = new HardwareTicket(...); → ✅ OK! HardwareTicket ist eine konkrete Klasse.
Ticket[] tickets = new Ticket[6]; → ✅ OK! Das Array selbst ist kein Objekt.

NetzwerkTicket.java – Dynamische Priorität
if/else Logik je nach Anzahl betroffener Nutzer
▼
📋 Schritt-für-Schritt: So löst du das
  1. Neue Klasse NetzwerkTicket extends Ticket
  2. Attribute: private String betroffenesSystem; und private int anzahlBetroffeneBenutzer;
  3. Konstruktor mit super(...) und eigenen Feldern
  4. In prioritaetBerechnen(): if/else-Logik schreiben:

NetzwerkTicket.java
public class NetzwerkTicket extends Ticket {

    private String betroffenesSystem;         // "WLAN", "VPN", "LAN"
    private int    anzahlBetroffeneBenutzer;  // Wie viele Personen betroffen?

    public NetzwerkTicket(String ticketnummer, String titel, String beschreibung,
                           String status, String betroffenesSystem, int anzahlBetroffeneBenutzer) {
        super(ticketnummer, titel, beschreibung, status);
        this.betroffenesSystem         = betroffenesSystem;
        this.anzahlBetroffeneBenutzer  = anzahlBetroffeneBenutzer;
    }

    @Override
    public void datenAusgeben() {
        basisDatenAusgeben();
        System.out.println("Betr. System: " + betroffenesSystem);
        System.out.println("Betr. Nutzer: " + anzahlBetroffeneBenutzer);
        System.out.println("Priorität:    " + prioritaetBerechnen());
    }

    // Die Priorität wird DYNAMISCH berechnet – je nach Anzahl betroffener Nutzer!
    // Das macht Polymorphie besonders mächtig: Die Logik steckt im Objekt selbst.
    @Override
    public String prioritaetBerechnen() {
        if (anzahlBetroffeneBenutzer > 10) {
            return "Hoch";    // Viele Nutzer → kritisch, sofort beheben!
        } else if (anzahlBetroffeneBenutzer > 3) {
            return "Mittel";  // Einige Nutzer → bald beheben
        } else {
            return "Niedrig"; // Wenige Nutzer → kann warten
        }
    }
}

⚡
Polymorphie in einem Satz

Gleicher Methodenaufruf, unterschiedliches Verhalten – Java entscheidet erst zur Laufzeit anhand des tatsächlichen Objekts (dynamischer Typ), welche Version der Methode ausgeführt wird. Dieser Mechanismus heißt dynamisches Binden (Late Binding).

✅ Was Polymorphie ermöglicht

• Unterschiedliche Objekte in einem Array speichern
• Eine Schleife für alle Typen
• Eine Methode mit Oberklassen-Parameter
• Neue Klassen hinzufügen ohne bestehenden Code zu ändern

🔑 Die 3 Schlüssel dazu

1. extends – Klasse erbt von Oberklasse
2. @Override – Methode überschreiben
3. Variable vom Oberklassen-Typ → Unterklassen-Objekt
