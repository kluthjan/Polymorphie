Rote Unterstreichungen in Eclipse?

Das ist ein Fehler. Fahre mit der Maus drüber – Eclipse erklärt was falsch ist. Häufige Ursachen: Tippfehler im Methodennamen, fehlendes Semikolon ;, oder eine Klasse nicht mit extends verknüpft.

Grundlagen

Was bedeuten die wichtigsten Begriffe?

Lies diesen Abschnitt zuerst, bevor du mit den Aufgaben anfängst. Hier wird alles einfach erklärt – mit Beispielen aus dem echten Leben.

📦
Was ist eine Klasse?

Eine Klasse ist ein Bauplan. Wie ein Formular, das beschreibt: "Welche Felder hat dieses Ding?" und "Was kann dieses Ding tun?"

Beispiel aus dem Leben: Der Bauplan eines Autos sagt: Es hat 4 Räder, eine Farbe, einen Motor. Und es kann fahren und bremsen. Das ist die Klasse. Ein konkretes Auto auf der Straße ist dann ein Objekt – gebaut nach diesem Bauplan.

Beispiel: Klasse
// Das ist eine Klasse – ein Bauplan:
public class Auto {
    // Felder (Eigenschaften)
    private String farbe = "rot";
    private int anzahlRaeder = 4;

    // Methode (was das Auto tun kann)
    public void fahren() {
        System.out.println("Das Auto fährt!");
    }
}
🧬
Was ist Vererbung? (extends)

Vererbung bedeutet: Eine Klasse übernimmt alles von einer anderen Klasse.

Beispiel: Stell dir vor, du hast eine Klasse Tier. Ein Hund IST ein Tier – er hat also alles, was ein Tier hat, plus noch mehr (z.B. er kann apportieren). Mit extends sagst du Java: "Hund IST EIN Tier. Gib Hund alles, was Tier hat."

🎭 Analogie aus dem echten Leben

Denk an eine Stellenausschreibung: "Wir suchen einen Software-Entwickler (extends Entwickler)." Der Software-Entwickler hat alles, was ein normaler Entwickler hat (kann Code schreiben, trifft Deadlines) – plus Software-spezifisches Wissen.

extends – Vererbung
// Hund erbt von Tier → Hund IST EIN Tier
public class Hund extends Tier {
    // Hund bekommt automatisch ALLES aus der Klasse Tier
    // Er muss nicht nochmal alles neu schreiben!
}
💡
Merksatz für extends

Wenn du sagen kannst "X IST EIN Y", dann macht extends Sinn.
✅ Laptop IST EIN Gerät → class Laptop extends Geraet
✅ Hund IST EIN Tier → class Hund extends Tier
❌ Gerät IST EIN Laptop → FALSCH! (nicht alle Geräte sind Laptops)

🔧
Was bedeutet @Override?

@Override bedeutet: Ich überschreibe eine Methode der Oberklasse. Die Methode hat denselben Namen wie in der Oberklasse, aber ein anderes Verhalten.

Einfach erklärt: Tier sagt "Ich kann Geräusche machen." Hund sagt: "Ja, aber ich belle – nicht das allgemeine Tiergeräusch."

❌ OHNE @Override

Wenn du den Methodennamen falsch tippst (geraeuschMache statt geraeuschMachen), bemerkt Eclipse das NICHT. Du denkst du überschreibst, aber du erstellst eine neue Methode!

✅ MIT @Override

Eclipse prüft: "Gibt es diese Methode in der Oberklasse?" Wenn nicht → roter Fehler. Das schützt dich vor Tippfehlern!

@Override Beispiel
public class Hund extends Tier {

    @Override  ← schreibe das GENAU SO, in der Zeile direkt über der Methode
    public void geraeuschMachen() {  ← gleicher Name wie in Tier!
        System.out.println("Der Hund bellt.");
        // Jetzt gibt der Hund "Der Hund bellt." aus, nicht das Allgemeine
    }
}
⬆️
Was bedeutet super() und super.methode()?

super bedeutet: Greife auf die Oberklasse zu. Es gibt zwei Verwendungen:

super(...) im Konstruktor

Ruft den Konstruktor der Oberklasse auf. Muss die erste Zeile im Konstruktor sein!
Damit werden die Felder der Oberklasse befüllt.

Beispiel: super("IT-1001", "Lenovo", ...); befüllt inventarnummer, hersteller usw. in Geraet.

super.methode() in einer Methode

Ruft die Version der Methode aus der Oberklasse auf. Nützlich wenn du erst die Basis-Ausgabe willst, dann deine eigene ergänzen möchtest.

Beispiel: super.datenAusgeben(); gibt Inventarnummer, Hersteller usw. aus – dann ergänzt Laptop den RAM.

⚠️
super() MUSS die ERSTE Zeile im Konstruktor sein!

Eclipse meckert sofort wenn das nicht so ist. Java braucht das, damit die Oberklasse vollständig eingerichtet ist, bevor die Unterklasse ihre Felder befüllt.

🔍
Statischer Typ vs. Dynamischer Typ – Das Herzstück!

Das ist der wichtigste Punkt für das Verständnis von Polymorphie. Schau dir diese Zeile an:

Zwei Typen in einer Zeile
  Geraet    geraet1  =    new Laptop(...)  ;
    ↑                              ↑
Statischer Typ                Dynamischer Typ
(links bei der Variable)      (rechts bei new)
(was der COMPILER sieht)      (was WIRKLICH im Speicher liegt)
🔴 Statischer Typ = Geraet

Was der Compiler sieht. Bevor das Programm läuft, prüft Eclipse/Java: "Welche Methoden darf man aufrufen?" Nur Methoden, die in Geraet definiert sind, sind erlaubt. Laptop-spezifische Methoden sind nicht direkt aufrufbar wenn der Typ Geraet ist.

🟢 Dynamischer Typ = Laptop

Was zur Laufzeit wirklich da ist. Wenn das Programm läuft und datenAusgeben() aufgerufen wird, schaut Java: "Was liegt wirklich in dieser Variable?" → Ein Laptop. Also wird Laptop.datenAusgeben() ausgeführt – nicht Geraet.datenAusgeben().

🎭 Analogie: Personalausweis vs. Beruf

Stell dir vor, du fragst jemanden: "Zeig mir deinen Ausweis!" Der Ausweis sagt "Person" (statischer Typ). Aber wer die Person wirklich ist – z.B. ein Arzt – das weißt du erst wenn du sie genauer kennst (dynamischer Typ). Wenn du sagst "Bitte heile mich!" (Methodenaufruf), reagiert die Person als Arzt – weil das ihr tatsächlicher Beruf ist.

🎯
Das ist Polymorphie!

Der Methodenaufruf ist bei allen Variablen gleich (datenAusgeben()). Aber Java führt automatisch die richtige Version aus – je nachdem was wirklich in der Variable steckt. Dieser Mechanismus heißt dynamisches Binden oder auf Englisch: Late Binding.

🔒
Was bedeutet private? (Kapselung)

private bedeutet: Dieses Feld/diese Methode ist von außen NICHT direkt zugänglich.

Wenn inventarnummer private ist, kann man von außerhalb der Klasse nicht einfach geraet1.inventarnummer = "XYZ" schreiben. Man braucht dafür spezielle Methoden – Getter (lesen) und Setter (schreiben).

🏦 Analogie: Bankschließfach

Stell dir vor, dein Kontostand ist private. Du kannst ihn nicht direkt anfassen. Du musst über die Bank gehen (getKontostand()) um ihn zu lesen, oder eine Einzahlung machen (einzahlen(100)) um ihn zu ändern. Das schützt vor unkontrollierter Manipulation.

private + Getter/Setter
private String status;   // private = von außen nicht direkt änderbar

// Getter: erlaubt das Lesen von außen
public String getStatus() {
    return status;   // gibt den Wert zurück
}

// Setter: erlaubt das Ändern von außen (kontrolliert!)
public void setStatus(String status) {
    this.status = status;   // setzt den neuen Wert
}
⚡
Was ist ein boolean?

Ein boolean kann nur zwei Werte haben: true (wahr) oder false (falsch). Er wird verwendet für Ja/Nein-Fragen.

true

Ja, ist so. Beispiel: managed = true → Der Switch ist managed (konfigurierbar).

false

Nein, ist nicht so. Beispiel: managed = false → Der Switch ist unmanaged (einfach).

boolean und ternärer Operator
private boolean managed;   // nur true oder false möglich!

// Ternärer Operator – eine Kurzform für if/else:
// (Bedingung) ? "Wert wenn true" : "Wert wenn false"
System.out.println("Managed: " + (managed ? "Ja" : "Nein"));
// Wenn managed=true  → Ausgabe: "Managed: Ja"
// Wenn managed=false → Ausgabe: "Managed: Nein"
Hauptaufgabe 1

Tiere – der einfachste Einstieg in Polymorphie

Was du hier lernst: Du erstellst eine Oberklasse (Tier) und drei Unterklassen (Hund, Katze, Kuh). Alle Unterklassen überschreiben dieselbe Methode mit ihrem eigenen Verhalten. Dann rufst du alle mit einer einheitlichen Variable vom Typ Tier auf.

🐾 Was diese Aufgabe zeigen soll

Stell dir vor, du bist Tierpfleger und rufst alle Tiere: "Macht euer Geräusch!" (geraeuschMachen()). Du rufst das bei jedem Tier gleich auf. Aber der Hund bellt, die Katze miaut, die Kuh muht – jedes Tier reagiert anders auf denselben Befehl. Das ist Polymorphie.

Tier ← Oberklasse
Hund extends Tier → "Der Hund bellt."
Katze extends Tier → "Die Katze miaut."
Kuh extends Tier → "Die Kuh muht."
1
Tier.java erstellen – Die Oberklasse
Neue Java-Datei anlegen und die Methode schreiben
▼

Was ist die Aufgabe hier? Du erstellst die Klasse Tier. Sie hat eine einzige Methode: geraeuschMachen(). Diese Methode gibt einfach aus: "Das Tier macht ein Geräusch." Die Unterklassen werden diese Methode später überschreiben.

🖥️ So erstellst du Tier.java in Eclipse
  1. Rechtsklick auf den Ordner src im Package Explorer (links)
  2. Klicke auf New → Class
  3. Bei "Name" schreibe: Tier
  4. Stelle sicher: Kein Häkchen bei "public static void main..."
  5. Klicke Finish
  6. Eclipse erstellt die Datei. Du siehst:
    public class Tier { }
  7. Schreibe die Methode zwischen die geschweiften Klammern
  8. Speichern: Strg + S

Was bedeutet public void geraeuschMachen()?
public = von überall aufrufbar
void = gibt nichts zurück (kein Rückgabewert)
geraeuschMachen = der Name der Methode
() = keine Parameter (man muss nichts übergeben um die Methode aufzurufen)

Tier.java – vollständige Lösung
// Das ist die Oberklasse "Tier".
// Sie ist der allgemeine Bauplan für alle Tierarten.
// Hund, Katze und Kuh werden von hier erben (extends Tier).
public class Tier {

    // Das ist die Methode. Sie gibt ein allgemeines Geräusch aus.
    // Unterklassen werden sie mit @Override überschreiben.
    public void geraeuschMachen() {
        System.out.println("Das Tier macht ein Geräusch.");
    }

// ← Diese Klammer schließt die Klasse Tier ab!
}
💡
System.out.println() – was bedeutet das?

System.out.println("Text"); gibt Text in der Eclipse-Console aus. println steht für "print line" – es druckt eine Zeile und macht dann einen Zeilenumbruch. Vergiss das Semikolon ; am Ende nicht!

Hund.java erstellen – Erste Unterklasse
extends Tier schreiben + @Override + neue Ausgabe
▼

Was passiert hier? Der Hund erbt alles von Tier. Aber er macht SEINEN Laut – nicht das allgemeine "Das Tier macht ein Geräusch." Dafür überschreiben wir die Methode mit @Override.

🖥️ So erstellst du Hund.java in Eclipse
  1. Rechtsklick auf src → New → Class
  2. Name: Hund
  3. Bei "Superclass" kannst du Tier eintippen – oder du schreibst extends Tier später manuell in den Code
  4. Klicke Finish
  5. Ergänze extends Tier in der Klassendeklaration falls noch nicht da
  6. Schreibe @Override und dann die Methode
  7. Speichern: Strg + S
⚠️
Häufiger Fehler: Methodenname falsch schreiben

Die Methode muss exakt so heißen wie in Tier: geraeuschMachen (mit großem M!). Mit @Override zeigt Eclipse sofort einen Fehler wenn der Name falsch ist. Das schützt dich!

Hund.java – vollständige Lösung
// Hund erbt von Tier mit "extends Tier"
// Das bedeutet: Hund IST EIN Tier!
public class Hund extends Tier {

    @Override  ← Diese Zeile muss direkt über der Methode stehen!
    public void geraeuschMachen() {
        // Hier definieren wir: DER HUND macht DIESEN Laut.
        // Nicht mehr "Das Tier macht ein Geräusch."
        System.out.println("Der Hund bellt.");
    }
}

Jetzt machst du dasselbe für Katze und Kuh – exakt gleicher Aufbau, nur anderer Klassenname und andere Ausgabe:

Katze.java
public class Katze extends Tier {
    @Override
    public void geraeuschMachen() {
        System.out.println("Die Katze miaut.");
    }
}
Kuh.java
public class Kuh extends Tier {
    @Override
    public void geraeuschMachen() {
        System.out.println("Die Kuh muht.");
    }
}
3
Main.java – Polymorphie sehen!
Variablen vom Typ Tier, Objekte von Hund/Katze/Kuh
▼

Jetzt kommt der spannende Teil! Du erstellst drei Variablen – alle mit dem Typ Tier. Aber du legst dort Objekte von Hund, Katze und Kuh rein. Dann rufst du bei allen dieselbe Methode auf – und Java führt automatisch die richtige aus.

🔑
Der entscheidende Unterschied

Tier tier1 = new Hund(); – hier sind zwei Dinge:
→ Tier tier1: Die Variable heißt tier1 und hat den Typ Tier (statischer Typ)
→ new Hund(): Im Speicher liegt aber ein Hund-Objekt (dynamischer Typ)
→ Wenn du tier1.geraeuschMachen() aufrufst, schaut Java: "Was liegt wirklich in tier1?" → Hund → ruft Hund.geraeuschMachen() auf!

Main.java – Hauptaufgabe 1 vollständig
public class Main {
    public static void main(String[] args) {

        // STATISCHER TYP: Tier (steht links)
        // DYNAMISCHER TYP: Hund (steht rechts nach "new")
        Tier tier1 = new Hund();
        Tier tier2 = new Katze();
        Tier tier3 = new Kuh();

        // GLEICHER AUFRUF bei allen dreien:
        tier1.geraeuschMachen(); // Java: "Was ist tier1 wirklich?" → Hund → "Der Hund bellt."
        tier2.geraeuschMachen(); // Java: "Was ist tier2 wirklich?" → Katze → "Die Katze miaut."
        tier3.geraeuschMachen(); // Java: "Was ist tier3 wirklich?" → Kuh → "Die Kuh muht."

        // ERKLÄRUNG warum das Polymorphie ist (Schritt 6 der Aufgabe):
        // Alle drei Variablen haben den Typ Tier (statischer Typ).
        // Tatsächlich sind es aber Hund, Katze und Kuh (dynamischer Typ).
        // Java schaut erst zur Laufzeit welches Objekt wirklich drin steckt.
        // Dann ruft Java die passende überschriebene Methode auf.
        // Gleicher Code → unterschiedliche Ausgabe → DAS ist Polymorphie!
    }
}
🖥️ Ausgabe in der Eclipse-Console
Der Hund bellt.
Die Katze miaut.
Die Kuh muht.
🚨
Häufiger Fehler: Falscher Typ für die Variable

Wenn du schreibst: Hund tier1 = new Hund(); → Das funktioniert auch, aber dann ist es KEINE Polymorphie mehr! Der Typ muss Tier (die Oberklasse) sein, damit Java zur Laufzeit entscheiden muss welche Methode aufgerufen wird.

Hauptaufgabe 2

IT-Geräte – Praxisnahes Beispiel

Was du hier lernst: Du baust eine Klasse mit privaten Feldern, einem Konstruktor und Getter/Setter. Dann erstellst du Unterklassen mit zusätzlichen Feldern. Du wirst super() und super.methode() benutzen.

💼 Was diese Aufgabe zeigt

In einer IT-Abteilung gibt es verschiedene Geräte. Alle Geräte haben gemeinsame Infos (Inventarnummer, Hersteller, Modell, Standort, Status). Ein Laptop hat zusätzlich RAM. Ein Drucker hat ein Druckverfahren. Ein Switch hat Ports.

Ohne Vererbung: Du müsstest Inventarnummer, Hersteller usw. in jeder Klasse neu schreiben – dreimal. Das ist viel zu viel Aufwand!
Mit Vererbung: Du schreibst es einmal in Geraet, und Laptop/Drucker/Switch erben es automatisch.

Geraet ← inventarnummer, hersteller, modell, standort, status
Laptop + ramGb (int) – z.B. 16 oder 32
Drucker + druckverfahren (String) – z.B. "Laserdruck"
Switch + anzahlPorts (int) + managed (boolean)
1
Geraet.java – Die Oberklasse mit Feldern und Konstruktor
private Felder · Konstruktor · this · Getter/Setter · datenAusgeben()
▼

Was musst du hier erstellen?

📋 Schritt für Schritt – was schreibst du in Geraet.java?
  1. Oben in die Klasse: 5 private Felder (inventarnummer, hersteller, modell, standort, status) – alle als String
  2. Dann: Konstruktor mit allen 5 Parametern – befülle jedes Feld mit this.xyz = xyz
  3. Dann: Getter getStatus() – gibt return status; zurück
  4. Dann: Setter setStatus(String status) – setzt this.status = status;
  5. Dann: Methode datenAusgeben() – gibt alle 5 Felder aus
📌
Was ist ein Konstruktor?

Ein Konstruktor ist eine spezielle Methode, die aufgerufen wird wenn du new Geraet(...) schreibst. Er hat denselben Namen wie die Klasse und hat KEIN void. Im Konstruktor befüllst du die Felder des Objekts mit den Werten, die du beim new angibst.

💡
Was bedeutet this.inventarnummer = inventarnummer?

this.inventarnummer = das Feld dieser Klasse (das Attribut)
inventarnummer ohne this = der Parameter, den man beim Aufruf übergibt
Da beide gleich heißen, brauchst du this um zu sagen: "Ich meine das Klassen-Attribut, nicht den Parameter."

Geraet.java – vollständige Lösung mit Erklärungen
public class Geraet {

    // ═══════════════════════════════════════════════════════
    // FELDER (auch "Attribute" genannt)
    // private = von außen nicht direkt änderbar (Kapselung!)
    // ═══════════════════════════════════════════════════════
    private String inventarnummer;   // z.B. "IT-1001"
    private String hersteller;        // z.B. "Lenovo"
    private String modell;            // z.B. "ThinkPad T14"
    private String standort;          // z.B. "Raum 101"
    private String status;            // "aktiv" / "offline" / "wartung"

    // ═══════════════════════════════════════════════════════
    // KONSTRUKTOR
    // Wird aufgerufen wenn man: new Geraet("IT-1001", ...) schreibt
    // Der Name muss EXAKT gleich sein wie der Klassenname!
    // Kein "void" beim Konstruktor!
    // ═══════════════════════════════════════════════════════
    public Geraet(String inventarnummer, String hersteller,
                   String modell, String standort, String status) {

        // "this.inventarnummer" = das FELD dieser Klasse
        // "inventarnummer"      = der PARAMETER des Konstruktors
        // Beide heißen gleich → deshalb brauchen wir "this"!
        this.inventarnummer = inventarnummer;
        this.hersteller     = hersteller;
        this.modell         = modell;
        this.standort       = standort;
        this.status         = status;
    }

    // ═══════════════════════════════════════════════════════
    // GETTER – erlaubt das Lesen des Status von außen
    // ═══════════════════════════════════════════════════════
    public String getStatus() {
        return status;   // gibt den aktuellen Wert zurück
    }

    // ═══════════════════════════════════════════════════════
    // SETTER – erlaubt das Ändern des Status von außen
    // ═══════════════════════════════════════════════════════
    public void setStatus(String status) {
        this.status = status;   // setzt den neuen Wert
    }

    // ═══════════════════════════════════════════════════════
    // METHODE: datenAusgeben()
    // Gibt alle gemeinsamen Felder aus.
    // Unterklassen rufen diese Version mit super.datenAusgeben() auf!
    // ═══════════════════════════════════════════════════════
    public void datenAusgeben() {
        System.out.println("Inventarnummer: " + inventarnummer);
        System.out.println("Hersteller:     " + hersteller);
        System.out.println("Modell:         " + modell);
        System.out.println("Standort:       " + standort);
        System.out.println("Status:         " + status);
    }
}
2
Laptop.java – Unterklasse mit super()
extends Geraet · super() als erste Zeile · @Override · super.datenAusgeben()
▼

Was passiert im Konstruktor? Der Laptop-Konstruktor bekommt 6 Parameter (alle von Geraet plus den RAM). Die ersten 5 gibt er direkt an Geraet weiter mit super(...). Dann kümmert er sich nur noch um seinen eigenen Wert (ramGb).

new Laptop(..., 16)
→
super(...) → Geraet befüllt seine 5 Felder
→
this.ramGb = 16
→
Laptop fertig!
⚠️
Warum kann Laptop nicht direkt auf inventarnummer zugreifen?

Die Felder in Geraet sind private. Das bedeutet: Selbst Unterklassen können sie nicht direkt ansprechen! Deshalb rufen wir super.datenAusgeben() auf – das erledigt Geraet für uns. Geraet hat Zugriff auf seine eigenen privaten Felder und gibt sie aus.

Laptop.java – vollständige Lösung mit Erklärungen
public class Laptop extends Geraet {   ← Laptop IST EIN Geraet

    // Laptop-eigenes Feld (zusätzlich zu den Geraet-Feldern)
    private int ramGb;   ← int = Ganzzahl, z.B. 16 oder 32

    // KONSTRUKTOR
    // Nimmt alle Geraet-Parameter PLUS den Laptop-eigenen Parameter (ramGb)
    public Laptop(String inventarnummer, String hersteller, String modell,
                   String standort, String status, int ramGb) {

        // MUSS die ALLERERSTE Zeile sein!
        super(inventarnummer, hersteller, modell, standort, status);
                ↑ Ruft den Geraet-Konstruktor auf
                  Geraet befüllt dann seine eigenen 5 Felder

        this.ramGb = ramGb;   ← Laptop kümmert sich nur noch um seinen eigenen Wert
    }

    // METHODE ÜBERSCHREIBEN
    @Override
    public void datenAusgeben() {
        super.datenAusgeben();
                ↑ Ruft Geraet.datenAusgeben() auf
                  Das gibt Inventarnummer, Hersteller, Modell, Standort, Status aus
                  Wir machen das so, weil wir nicht direkt auf die privaten
                  Felder von Geraet zugreifen können!

        // DANACH kommt unser Laptop-spezifischer Teil:
        System.out.println("RAM:            " + ramGb + " GB");
    }
}
🖥️ Was die Ausgabe von datenAusgeben() bei einem Laptop zeigt

Hauptaufgabe 3

Polymorphes Array & Schleife

Was du hier lernst: Du speicherst verschiedene Objekte (Laptop, Drucker, Switch) alle zusammen in einem Array der Oberklasse. Dann gibst du sie mit einer einzigen Schleife aus. Du zählst Geräte nach Status und änderst einen Status.

📦 Warum ist das so praktisch?

Stell dir eine Inventarliste vor. Ohne Polymorphie bräuchtest du 3 Listen: Eine für Laptops, eine für Drucker, eine für Switches. Und 3 separate Schleifen. Mit Polymorphie hast du eine Liste und eine Schleife – die funktioniert für alle Geräte automatisch.

Wenn du später z.B. eine neue Klasse Tablet hinzufügst, kannst du sie einfach in das Array packen – die Schleife funktioniert ohne Änderungen weiterhin!

1
Array erstellen und befüllen
Geraet[] mit 6 Elementen – 2 Laptops, 2 Drucker, 2 Switches
▼
💡
Warum kann ein Laptop in ein Geraet[] gespeichert werden?

Laptop extends Geraet → Laptop IST EIN Geraet.
Ein Geraet[]-Array speichert alles, was ein Geraet ist.
Weil Laptop ein Geraet ist, passt er rein.
Genauso: Ein Tier[]-Array nimmt Hund, Katze und Kuh – weil alle Tiere sind.

Schleife – alle Geräte ausgeben
for-Schleife mit i von 0 bis geraete.length
▼
💡
Wie funktioniert eine for-Schleife?

for (int i = 0; i < geraete.length; i++)
→ int i = 0: Starte bei Index 0 (erstes Element)
→ i < geraete.length: Mache weiter solange i kleiner als 6 ist (also: 0,1,2,3,4,5)
→ i++: Nach jedem Durchlauf: i um 1 erhöhen
→ geraete[i]: Das Element am aktuellen Index

Main.java – Schleife ausgeben
for (int i = 0; i < geraete.length; i++) {
    System.out.println("--- Gerät " + (i + 1) + " ---");
    // i=0: Gerät 1, i=1: Gerät 2 usw. → deshalb (i+1)!

    geraete[i].datenAusgeben();
        ↑ GLEICHER AUFRUF jedes Mal – aber Java führt die richtige Version aus:
          i=0: geraete[0] ist Laptop  → Laptop.datenAusgeben()  (RAM ausgeben)
          i=2: geraete[2] ist Drucker → Drucker.datenAusgeben() (Druckverfahren)
          i=4: geraete[4] ist Switch  → Switch.datenAusgeben()  (Ports + Managed)

}

🚨
WICHTIG: Strings vergleiche NIEMALS mit ==

status == "aktiv" → ❌ FALSCH! Vergleicht Speicheradressen, nicht den Text.
status.equals("aktiv") → ✅ RICHTIG! Vergleicht den tatsächlichen Text.
In Java muss man Strings immer mit .equals() vergleichen!

Main.java – Status auswerten und ändern
// ── Zähler für die drei Status-Varianten ─────────────────────────────
int aktiveGeraete  = 0;  ← Zähler starten bei 0
int offlineGeraete = 0;
int wartungGeraete = 0;

// Schleife: jedes Gerät prüfen
for (int i = 0; i < geraete.length; i++) {

    // getStatus() aufrufen → gibt den Status-String zurück
    String status = geraete[i].getStatus();

    // WICHTIG: Strings mit .equals() vergleichen, NICHT mit ==!
    if (status.equals("aktiv")) {
        aktiveGeraete++;   ← ++ bedeutet: um 1 erhöhen
    } else if (status.equals("offline")) {
        offlineGeraete++;
    } else if (status.equals("wartung")) {
        wartungGeraete++;
    }
}

// Ergebnis ausgeben
System.out.println("Aktive Geräte:  " + aktiveGeraete);   → 3
System.out.println("Offline Geräte: " + offlineGeraete);  → 1
System.out.println("Wartung:        " + wartungGeraete);  → 2

// ── Status eines Geräts ändern ────────────────────────────────────────
// geraete[3] ist der Canon-Drucker (Index 3 = 4. Element)
geraete[3].setStatus("aktiv");  ← Drucker wurde repariert!

Methode mit Oberklassen-Parameter

Idee: Eine Methode bekommt als Parameter den Oberklassen-Typ. Dann kann man beliebige Unterklassen übergeben – und die richtige Methode wird automatisch aufgerufen.

1
geraetAnzeigen(Geraet) schreiben und aufrufen
public static void geraetAnzeigen(Geraet geraet)
▼

Wo schreibst du diese Methode hin? Direkt in die Klasse Main, außerhalb von main(), aber noch innerhalb der geschweiften Klammer von class Main { }.

💡
Warum static?

Die Methode muss static sein, weil main() auch static ist. Statische Methoden gehören zur Klasse, nicht zu einem Objekt. Du kannst eine statische Methode aufrufen ohne vorher new Main() zu schreiben.

Main.java – Zusatzaufgabe 1

        geraetAnzeigen(new Drucker("IT-9002", "Brother", "HL-L3270", "Büro", "aktiv", "Laserdruck"));
        System.out.println();
        geraetAnzeigen(new Switch("IT-9003", "Netgear", "GS308", "Keller", "aktiv", 8, false));
    }

    // ← Diese Methode steht AUSSERHALB von main(), aber INNERHALB von class Main!
    // Parameter-Typ ist Geraet → man kann Laptop, Drucker UND Switch übergeben!
    public static void geraetAnzeigen(Geraet geraet) {
        System.out.println("=== Gerät ===");

    }
}

Schritt 2: In Main.java – das Problem und die Lösung:

Main.java – Zusatzaufgabe 2
Geraet g = new Laptop("IT-5001", "HP", "EliteBook", "Raum 3", "aktiv", 16);

// g.akkuStatusAusgeben(); ← COMPILERFEHLER! Eclipse zeigt roten Fehler!
// Warum? → Statischer Typ von g ist "Geraet"
// Geraet kennt akkuStatusAusgeben() nicht (es steht nur in Laptop!)
// Eclipse schaut beim Kompilieren nur auf den statischen Typ → Fehler!

// ── LÖSUNG: instanceof prüfen + Casting ──────────────────────────────
// instanceof prüft: Ist g wirklich ein Laptop?
if (g instanceof Laptop) {
    // Casting: Sage Java "behandle g als Laptop"
    // Das nennt man DOWNCASTING (von Oberklasse → Unterklasse)
    Laptop laptop = (Laptop) g;
    // ↑ Jetzt hat laptop den statischen Typ Laptop
    // ↑ Alle Laptop-Methoden sind verfügbar!

    laptop.akkuStatusAusgeben();  ← ✅ Kein Fehler!
}

// KOMMENTAR für die Aufgabe:
// Warum brauchen wir instanceof und Casting?
// → g hat den statischen Typ Geraet → nur Geraet-Methoden aufrufbar
// → akkuStatusAusgeben() ist aber nur in Laptop → nicht erreichbar!
// → instanceof prüft SICHER ob g wirklich ein Laptop ist
// → Casting "(Laptop) g" sagt Java: "Behandle g als Laptop"
// → Ohne instanceof: wenn g kein Laptop wäre → ClassCastException (Laufzeitfehler!)
Zusatzaufgabe 3

Abstrakte Klassen

Was bedeutet abstract? Eine abstrakte Klasse ist eine Klasse, von der du kein Objekt direkt erstellen kannst. Sie dient nur als Vorlage für Unterklassen.

1
Was ist abstract und wozu braucht man es?
abstract class · abstract void · warum kein new möglich
▼
🏗️ Analogie: Bauplan

Ein Bauplan beschreibt, was ein Haus haben soll (Zimmer, Türen, Fenster). Aber man kann nicht im Bauplan wohnen – man braucht ein konkretes Haus. Eine abstrakte Klasse ist der Bauplan. Die Unterklassen sind die konkreten Häuser.

❌ Nicht erlaubt

new Ticket(...) → Compilerfehler!
"Cannot instantiate the type Ticket"
Man kann kein abstraktes Objekt erstellen.

✅ Erlaubt

new HardwareTicket(...) → OK!
HardwareTicket ist eine konkrete Unterklasse.
Sie hat alle abstrakten Methoden implementiert.

Ticket.java – abstrakte Klasse (für Zusatzaufgabe 4)
// "abstract" vor "class" → kein new Ticket() möglich!
public abstract class Ticket {

    protected String ticketnummer;   ← protected = auch für Unterklassen zugänglich
    protected String titel;
    protected String beschreibung;
    protected String status;

    public Ticket(String ticketnummer, String titel, String beschreibung, String status) {
        this.ticketnummer = ticketnummer;
        this.titel = titel;
        this.beschreibung = beschreibung;
        this.status = status;
    }

    // ABSTRAKTE METHODEN – kein Rumpf, kein {}!
    // Unterklassen MÜSSEN diese implementieren (sonst Compilerfehler!)
    public abstract void datenAusgeben();         ← kein {} !
    public abstract String prioritaetBerechnen(); ← kein {} !

    // NORMALE Methode (hat einen Rumpf) – von Unterklassen aufrufbar
    public void basisDatenAusgeben() {
        System.out.println("Ticketnummer: " + ticketnummer);
        System.out.println("Titel:        " + titel);
        System.out.println("Beschreibung: " + beschreibung);
        System.out.println("Status:       " + status);
    }
    public String getStatus() { return status; }
    public void setStatus(String s) { this.status = s; }
}
