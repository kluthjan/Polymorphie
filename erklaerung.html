Grundlagen

Was ist Polymorphie?

Polymorphie bedeutet: gleicher Methodenaufruf, aber unterschiedliches Verhalten, je nachdem welches Objekt tatsächlich dahintersteckt. Das ist eines der mächtigsten Konzepte in der objektorientierten Programmierung.

🎯
Das Kernprinzip kurz erklärt
Java
// Beide Variablen haben den Typ Geraet (statischer Typ)
Geraet geraet1 = new Laptop(...);   // dynamischer Typ: Laptop
Geraet geraet2 = new Drucker(...);  // dynamischer Typ: Drucker

// Gleicher Aufruf:
geraet1.datenAusgeben();   // → führt Laptop-Version aus!
geraet2.datenAusgeben();   // → führt Drucker-Version aus!

Java schaut zur Laufzeit auf das tatsächliche Objekt (was bei new steht) und ruft die richtige Methode auf – nicht die Version der Oberklasse.

📖 Schlüsselbegriffe auf einen Blick

extends
Klasse erbt von einer anderen.
class Hund extends Tier
super(...)
Konstruktor der Oberklasse aufrufen.
Muss als erstes im Konstruktor stehen!
super.methode()
Methode der Oberklasse aufrufen, z.B. super.datenAusgeben()
@Override
Markiert, dass diese Methode eine aus der Oberklasse überschreibt.
Statischer Typ
Steht links bei der Variable.
Geraet g = ...
Dynamischer Typ
Steht rechts bei new.
... = new Laptop(...)
abstract
Klasse/Methode ohne Implementierung. Kein new Klasse() möglich!
instanceof
Prüft den tatsächlichen Typ eines Objekts zur Laufzeit.
💡
Statisch vs. Dynamisch – so merkst du es dir

Statisch = was der Compiler sieht (links). Dynamisch = was zur Laufzeit wirklich da ist (rechts bei new). Java entscheidet nach dem dynamischen Typ, welche Methode ausgeführt wird!

Hauptaufgabe 1

Tiere – einfache Polymorphie

Wir starten mit einem einfachen Beispiel: Es gibt eine Oberklasse Tier und drei Unterklassen. Jede Unterklasse überschreibt dieselbe Methode mit ihrer eigenen Ausgabe.

Tier
Hund → "Der Hund bellt."
Katze → "Die Katze miaut."
Kuh → "Die Kuh muht."
1
Tier.java – Die Oberklasse
Basisklasse mit der Methode geraeuschMachen()
▼

Die Klasse Tier ist die Oberklasse (auch Basisklasse oder Superklasse genannt). Sie enthält die Methode geraeuschMachen() mit einer allgemeinen Ausgabe. Diese Methode werden die Unterklassen später überschreiben.

Tier.java
public class Tier {

    // Diese Methode gibt ein allgemeines Geräusch aus.
    // Die Unterklassen werden sie mit @Override überschreiben.
    public void geraeuschMachen() {
        System.out.println("Das Tier macht ein Geräusch.");
    }
}
📌
Was passiert hier?

Tier hat eine ganz normale Methode. Wenn wir direkt new Tier() machen und geraeuschMachen() aufrufen, kommt "Das Tier macht ein Geräusch." Aber die Unterklassen können das ändern!

2
Hund.java – Erste Unterklasse
extends Tier + @Override
▼

Mit extends Tier sagt man: "Hund ist ein Tier". Hund erbt automatisch alle Methoden von Tier. Mit @Override wird die Methode überschrieben – der Hund bellt jetzt statt das allgemeine Tiergeräusch zu machen.

Hund.java
public class Hund extends Tier {  // Hund IST ein Tier

    @Override  // Diese Methode existiert schon in Tier – wir überschreiben sie
    public void geraeuschMachen() {
        System.out.println("Der Hund bellt.");
        // NICHT mehr "Das Tier macht ein Geräusch."!
    }
}

Katze und Kuh werden genau gleich aufgebaut:

Katze.java & Kuh.java
public class Katze extends Tier {
    @Override
    public void geraeuschMachen() {
        System.out.println("Die Katze miaut.");
    }
}

public class Kuh extends Tier {
    @Override
    public void geraeuschMachen() {
        System.out.println("Die Kuh muht.");
    }
}
3
Main.java – Polymorphie in Aktion
Alle Variablen vom Typ Tier, aber unterschiedliche Objekte
▼

Jetzt kommt das Herzstück: Alle Variablen haben den statischen Typ Tier. Aber jede Variable zeigt auf ein anderes Objekt – und Java ruft deshalb die richtige Methode auf.

Main.java – Hauptaufgabe 1
// Statischer Typ = Tier (links)
// Dynamischer Typ = Hund / Katze / Kuh (rechts bei new)
Tier tier1 = new Hund();   // dynamisch: Hund
Tier tier2 = new Katze();  // dynamisch: Katze
Tier tier3 = new Kuh();    // dynamisch: Kuh

tier1.geraeuschMachen();  // Java: dynamischer Typ ist Hund → Hund.geraeuschMachen()
tier2.geraeuschMachen();  // Java: dynamischer Typ ist Katze → Katze.geraeuschMachen()
tier3.geraeuschMachen();  // Java: dynamischer Typ ist Kuh → Kuh.geraeuschMachen()

// Alle Variablen haben den Typ Tier (statischer Typ).
// Tatsächlich sind es Hund, Katze und Kuh (dynamischer Typ).
// Java entscheidet zur Laufzeit, welche Methode aufgerufen wird → Polymorphie!
🖥️ Ausgabe in Eclipse
Der Hund bellt.
Die Katze miaut.
Die Kuh muht.
✅
Warum ist das Polymorphie?

Der Aufruf geraeuschMachen() ist bei allen drei Variablen identisch – aber die Ausgabe ist jeweils verschieden. Java schaut beim Aufruf auf das tatsächliche Objekt und führt die passende Version aus. Das nennt man dynamisches Binden (Late Binding).

Hauptaufgabe 2

IT-Geräte polymorph verwalten

Jetzt auf ein praxisnahes IT-Beispiel: Ein Unternehmen verwaltet Laptops, Drucker und Switches. Alle sind "Geräte" – aber jedes Gerät hat zusätzlich eigene Daten.

Geraet (inventarnummer, hersteller, modell, standort, status)
Laptop → + ramGb (int)
Drucker → + druckverfahren (String)
Switch → + anzahlPorts (int), managed (boolean)
1
Geraet.java – Die Oberklasse mit Attributen
private Attribute, Konstruktor, Getter/Setter, datenAusgeben()
▼

Kapselung: Die Attribute sind private – von außen kann man sie nicht direkt lesen oder ändern. Dafür gibt es Getter (getStatus()) und Setter (setStatus(...)).

Geraet.java
public class Geraet {

    // private = nur innerhalb dieser Klasse direkt zugänglich
    private String inventarnummer;
    private String hersteller;
    private String modell;
    private String standort;
    private String status;

    // Konstruktor: wird aufgerufen wenn man new Geraet(...) schreibt
    // "this.xyz" = Attribut dieser Klasse, "xyz" = der Parameter
    public Geraet(String inventarnummer, String hersteller,
                   String modell, String standort, String status) {
        this.inventarnummer = inventarnummer;
        this.hersteller = hersteller;
        this.modell = modell;
        this.standort = standort;
        this.status = status;
    }

    // Getter: gibt den Status zurück (lesbar von außen)
    public String getStatus() { return status; }

    // Setter: ändert den Status (schreibbar von außen)
    public void setStatus(String status) { this.status = status; }

    // Diese Methode wird in den Unterklassen mit @Override erweitert
    public void datenAusgeben() {
        System.out.println("Inventarnummer: " + inventarnummer);
        System.out.println("Hersteller:     " + hersteller);
        System.out.println("Modell:         " + modell);
        System.out.println("Standort:       " + standort);
        System.out.println("Status:         " + status);
    }
}
2
Laptop.java – Unterklasse mit super()
extends Geraet, super(...), @Override datenAusgeben
▼

Der Laptop erbt von Geraet. Im Konstruktor muss als erstes super(...) aufgerufen werden – das gibt die gemeinsamen Werte an den Geraet-Konstruktor weiter. Dann speichert der Laptop nur noch seinen eigenen Wert (ramGb).

new Laptop("IT-1001", "Lenovo", ..., 16)
→
super("IT-1001", "Lenovo", ...) in Geraet
→
ramGb = 16 in Laptop
Laptop.java
public class Laptop extends Geraet {

    private int ramGb;  // nur Laptop hat dieses Attribut

    public Laptop(String inventarnummer, String hersteller, String modell,
                   String standort, String status, int ramGb) {
        super(inventarnummer, hersteller, modell, standort, status);
        // ↑ Ruft den Geraet-Konstruktor auf (muss ALS ERSTES stehen!)
        this.ramGb = ramGb;  // Laptop-eigener Wert
    }

    @Override
    public void datenAusgeben() {
        super.datenAusgeben();
        // ↑ Ruft Geraet.datenAusgeben() auf → gibt Inventarnummer, Hersteller usw. aus
        System.out.println("RAM:            " + ramGb + " GB");
        // ↑ Danach kommt der Laptop-spezifische Teil
    }
}
💡
Warum super.datenAusgeben()?

Die Attribute inventarnummer, hersteller usw. sind private in Geraet. Das Laptop-Objekt kann sie nicht direkt ansprechen! Deshalb rufen wir die Methode der Oberklasse auf, die das für uns erledigt. Dann ergänzen wir nur noch den RAM.

3
Drucker.java & Switch.java
Gleiches Muster, andere Attribute
▼
Drucker.java
public class Drucker extends Geraet {

    private String druckverfahren;  // z.B. "Laserdruck", "Tintenstrahl"

    public Drucker(String inventarnummer, String hersteller, String modell,
                    String standort, String status, String druckverfahren) {
        super(inventarnummer, hersteller, modell, standort, status);
        this.druckverfahren = druckverfahren;
    }

    @Override
    public void datenAusgeben() {
        super.datenAusgeben();                                           // allgemein
        System.out.println("Druckverfahren: " + druckverfahren);    // Drucker-spezifisch
    }
}
Switch.java
public class Switch extends Geraet {

    private int     anzahlPorts;  // z.B. 8, 24, 48
    private boolean managed;      // true = konfigurierbar, false = einfacher Switch

    public Switch(String inventarnummer, String hersteller, String modell,
                   String standort, String status, int anzahlPorts, boolean managed) {
        super(inventarnummer, hersteller, modell, standort, status);
        this.anzahlPorts = anzahlPorts;
        this.managed = managed;
    }

    @Override
    public void datenAusgeben() {
        super.datenAusgeben();
        System.out.println("Anzahl Ports:   " + anzahlPorts);
        // Ternärer Operator: Bedingung ? "wenn true" : "wenn false"
        System.out.println("Managed:        " + (managed ? "Ja" : "Nein"));
    }
}

Hauptaufgabe 3

Polymorphes Array mit Schleife

Polymorphie wird richtig mächtig, wenn man viele verschiedene Objekte gemeinsam speichert und verarbeitet. Ein Array der Oberklasse kann Objekte aller Unterklassen aufnehmen.

1
Array erstellen und befüllen
Geraet[] nimmt Laptop, Drucker und Switch auf
▼

Ein Geraet[]-Array kann jedes Objekt speichern, das von Geraet erbt. Das ist möglich weil Laptop IST ein Geraet (extends Geraet).

Main.java – Array befüllen
Geraet[] geraete = new Geraet[6];  // Array für 6 Geräte

// Laptops:
geraete[0] = new Laptop("IT-1001", "Lenovo", "ThinkPad T14",  "Raum 101",   "aktiv",   16);
geraete[1] = new Laptop("IT-1002", "Dell",   "Latitude 5440", "Raum 102",   "aktiv",   32);

// Drucker:
geraete[2] = new Drucker("IT-2001", "HP",    "LaserJet Pro", "Raum 204",   "aktiv",   "Laserdruck");
geraete[3] = new Drucker("IT-2002", "Canon", "Pixma G3570",  "Raum 205",   "offline", "Tintenstrahl");

// Switches:
geraete[4] = new Switch("IT-3001", "Cisco",   "CBS350",   "Serverraum", "wartung", 24, true);
geraete[5] = new Switch("IT-3002", "TP-Link", "TL-SG108", "Raum 110",   "aktiv",   8, false);

// Warum kann ein Laptop in Geraet[] gespeichert werden?
// → Laptop extends Geraet → Laptop IST ein Geraet
// → Genau wie: Ein Hund IST ein Tier und passt in ein Tier[]
2
Alle Geräte mit Schleife ausgeben
Immer gleicher Aufruf – verschiedene Ausgaben
▼
Main.java – Schleife
for (int i = 0; i < geraete.length; i++) {
    System.out.println("--- Gerät " + (i + 1) + " ---");
    geraete[i].datenAusgeben();  // Polymorphie! Immer gleicher Aufruf...
    // ...aber Java führt je nach Objekt die richtige Version aus:
    // i=0: Laptop.datenAusgeben()  → + RAM
    // i=2: Drucker.datenAusgeben() → + Druckverfahren
    // i=4: Switch.datenAusgeben()  → + Ports + Managed
    System.out.println();
}
🎯
Das ist der Vorteil von Polymorphie!

Statt 3 verschiedener Schleifen für Laptop, Drucker und Switch reicht eine einzige Schleife. Wenn du später eine neue Klasse Tablet hinzufügst, funktioniert die Schleife sofort – ohne Änderungen!

3
Status auswerten mit getStatus()
Aktiv / Offline / Wartung zählen
▼
Main.java – Status zählen
int aktiveGeraete  = 0;
int offlineGeraete = 0;
int wartungGeraete = 0;

for (int i = 0; i < geraete.length; i++) {
    String status = geraete[i].getStatus();  // Getter aus Geraet

    if (status.equals("aktiv")) {
        aktiveGeraete++;
    } else if (status.equals("offline")) {
        offlineGeraete++;
    } else if (status.equals("wartung")) {
        wartungGeraete++;
    }
}

System.out.println("Aktive Geräte:  " + aktiveGeraete);
System.out.println("Offline Geräte: " + offlineGeraete);
System.out.println("Wartung:        " + wartungGeraete);

// Status eines Geräts ändern:
geraete[3].setStatus("aktiv");  // Drucker wurde repariert!

Offline Geräte: 1
Wartung: 2

Zusatzaufgabe 2

instanceof und Casting

Was passiert wenn eine spezielle Methode nur in der Unterklasse existiert, die Variable aber den Typ der Oberklasse hat?

!
Das Problem – akkuStatusAusgeben() ist nicht erreichbar
Statischer Typ Geraet kennt die Methode nicht
▼

Laptop hat eine Methode akkuStatusAusgeben() – aber Geraet nicht. Wenn die Variable den Typ Geraet hat, kann Java diese Methode nicht finden!

Das Problem
Geraet g = new Laptop("IT-5001", "HP", "EliteBook", "Raum 3", "aktiv", 16);

// ❌ FEHLER – Compilerfehler!
// g.akkuStatusAusgeben();
// → "The method akkuStatusAusgeben() is undefined for the type Geraet"
// → Geraet kennt diese Methode nicht!
❌
Warum passiert das?

Der statische Typ (links bei der Variable) ist Geraet. Java erlaubt nur Methoden aufzurufen, die in Geraet definiert sind. akkuStatusAusgeben() existiert nur in Laptop – der Compiler sieht das nicht!

✓
Die Lösung – instanceof + Casting
Typ prüfen, dann sicher umwandeln
▼
Lösung: instanceof + Casting
Geraet g = new Laptop(...);

// Schritt 1: Sicher prüfen ob g wirklich ein Laptop ist
if (g instanceof Laptop) {
    // Schritt 2: Casten – sagen wir Java "behandle g als Laptop"
    Laptop laptop = (Laptop) g;  // Downcasting: Geraet → Laptop

    // Schritt 3: Jetzt geht die Laptop-Methode!
    laptop.akkuStatusAusgeben();  // ✅ Kein Fehler!
}

// Warum brauchen wir instanceof?
// → Ohne Prüfung könnte g ein Drucker sein → ClassCastException zur Laufzeit!
// → instanceof macht den Cast sicher
🖥️ Ausgabe
Akku wird geprüft.
BegriffErklärungBeispiel
instanceofPrüft ob ein Objekt von einem bestimmten Typ istg instanceof Laptop → true/false
CastingTyp "umwandeln" – Geraet zu Laptop machen(Laptop) g
DowncastingVon Oberklasse zu Unterklasse castenGeraet → Laptop
Zusatzaufgabe 3

Abstrakte Klassen

Manchmal soll eine Klasse nur als Vorlage dienen – man soll kein Objekt direkt davon erzeugen können. Dafür gibt es abstrakte Klassen.

🏗️
abstract – Bauplan ohne Objekt

Mit abstract vor der Klasse wird sie zur abstrakten Klasse. Das bedeutet: new Geraet() ist nicht mehr möglich! Aber new Laptop() geht weiterhin, weil Laptop konkret ist.

Abstrakte Methoden haben keinen Rumpf (keine geschweifte Klammer). Alle Unterklassen müssen diese Methode überschreiben – sonst gibt es einen Compilerfehler.

Ticket.java – abstrakte Klasse (Zusatzaufgabe 3 + 4)
// abstract = kein new Ticket() möglich!
public abstract class Ticket {

    protected String ticketnummer;
    protected String titel;
    protected String beschreibung;
    protected String status;

    public Ticket(String ticketnummer, String titel,
                   String beschreibung, String status) {
        this.ticketnummer = ticketnummer;
        this.titel = titel;
        this.beschreibung = beschreibung;
        this.status = status;
    }

    // Abstrakte Methoden – kein Rumpf (kein {})!
    // Jede Unterklasse MUSS diese implementieren:
    public abstract void datenAusgeben();
    public abstract String prioritaetBerechnen();

    // Normale Methode (hat einen Rumpf) – kann aufgerufen werden:
    public void basisDatenAusgeben() {
        System.out.println("Ticketnummer: " + ticketnummer);
        System.out.println("Titel:        " + titel);
        System.out.println("Beschreibung: " + beschreibung);
        System.out.println("Status:       " + status);
    }

    public String getStatus() { return status; }
    public void setStatus(String s) { this.status = s; }
}
⚠️
Wichtig:

new Ticket(...) → ❌ Compilerfehler! "Cannot instantiate the type Ticket"
new HardwareTicket(...) → ✅ Erlaubt! HardwareTicket ist konkret.

Zusatzaufgabe 4

Ticketsystem mit Polymorphie

Ein komplettes IT-Ticketsystem mit verschiedenen Ticketarten, eigener Prioritätslogik und Auswertung.

Ticket (abstrakt)
HardwareTicket → geraetetyp, standort | Priorität: immer "Mittel"
SoftwareTicket → softwareName, version | Priorität: immer "Niedrig"
NetzwerkTicket → betroffenesSystem, anzahlBetroffeneBenutzer | Priorität: dynamisch!
1
NetzwerkTicket.java – Dynamische Priorität
Priorität hängt von der Anzahl betroffener Nutzer ab
▼

Das NetzwerkTicket hat eine besonders interessante prioritaetBerechnen()-Methode: Die Priorität wird anhand der betroffenen Nutzer berechnet – das steckt im Objekt selbst!

NetzwerkTicket.java
public class NetzwerkTicket extends Ticket {

    private String betroffenesSystem;
    private int anzahlBetroffeneBenutzer;

    public NetzwerkTicket(String ticketnummer, String titel, String beschreibung,
                          String status, String betroffenesSystem, int anzahlBetroffeneBenutzer) {
        super(ticketnummer, titel, beschreibung, status);
        this.betroffenesSystem = betroffenesSystem;
        this.anzahlBetroffeneBenutzer = anzahlBetroffeneBenutzer;
    }

    @Override
    public void datenAusgeben() {
        basisDatenAusgeben();  // gemeinsame Felder aus Ticket
        System.out.println("Betr. System: " + betroffenesSystem);
        System.out.println("Betr. Nutzer: " + anzahlBetroffeneBenutzer);
        System.out.println("Priorität:    " + prioritaetBerechnen());
    }

    @Override
    public String prioritaetBerechnen() {
        if (anzahlBetroffeneBenutzer > 10) {
            return "Hoch";    // viele betroffen → kritisch!
        } else if (anzahlBetroffeneBenutzer > 3) {
            return "Mittel";  // einige betroffen
        } else {
            return "Niedrig"; // wenige betroffen
        }
    }
}

    else if (p.equals("Niedrig")) anzahlNiedrig++;
}

System.out.println("Priorität Hoch:    " + anzahlHoch);
System.out.println("Priorität Mittel:  " + anzahlMittel);
System.out.println("Priorität Niedrig: " + anzahlNiedrig);
🖥️ Ausgabe (Prioritäts-Auswertung)
Priorität Hoch: 1  ← NetzwerkTicket mit 25 Nutzern
Priorität Mittel: 3  ← NetzwerkTicket (5 Nutzer) + 2x HardwareTicket
Priorität Niedrig: 2  ← 2x SoftwareTicket
